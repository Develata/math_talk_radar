# SEC-003 logging review — 2026-09-09

Status: engineering review and regression evidence; **not maintainer approval**.
The release gate still requires an actual commit-bound RELEASE_REVIEW declaration.

## Scope and findings

Inspected the CLI stderr sink (`runtime::run`), source/interests/scholars config
loading, scan failure reporting, updater URL/redirect/request errors, and the
acceptance workflow's handling of review and publication declarations.

Two failures were reproduced against runtime sources at
`a97df91b499344961ad6bbc288519f78283cc037` using synthetic markers:

1. TOML Display emitted the failing input line and the rejected value. A
   synthetic string used where `enabled` expects a boolean appeared in stderr
   (exit 3). The same error conversion existed for interests and scholars.
2. Updater validation and transport/redirect failures reflected whole URLs,
   including userinfo or query parameters that can contain signed-download
   credentials. Two failing tests covered validation and missing redirect
   Location/request-timeout paths.

Corrections replace TOML Display with context and line/column; semantic source
validation emits only the constraint; updater errors omit raw URL/Location
values and remove the URL from reqwest errors. No real credential was used.

## Reproducible evidence

```bash
cargo test -p math_talk_radar --test integration sec_003_
cargo test -p math_talk_radar --lib sec_003_update
```

The tests exercise the real CLI's stdout/stderr for all three TOML overrides,
semantic source validation, and mock update request failures. They assert
synthetic sentinels do not appear while retaining exit codes and useful error
locations/categories. The initial failures were observed before correction.
